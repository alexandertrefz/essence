essence has no floating point. It has a **numeric tower** — four types, each
exact, each the smallest thing that can hold the values it holds — and an
operation that leaves one of them widens into the type that can still say the
answer rather than rounding.

<div class="table-scroll">

| Type | Holds | Written |
| --- | --- | --- |
| `Integer` | Whole numbers of arbitrary size | `42`, `9_007_199_254_740_991` |
| `Rational` | Exact ratios of integers, in lowest terms | `3/4`, `1/3` |
| `Algebraic` | Numbers of the form `a + b·√d` | `2::squareRoot()` |
| `Transcendental` | Numbers of the form `a + b·π` | `Number.Pi` |
| `Number` | All four, as one union | — |
| `Irrational` | `Algebraic \| Transcendental` | — |

</div>

## Integers

There is no `2^53` to fall off, and no wrap-around.

```essence
implementation {

	§ Integers are arbitrarily large — there is no 2^53 to fall off.
	Terminal.print(9_007_199_254_740_991::multiply(with 1000))

	Terminal.print(1234::subtract(234)) § 1000
	Terminal.print(2::raise(to 10)) § 1024
	Terminal.print(0::subtract(7)::remainder(dividingBy 3)) § 2 — never negative
	Terminal.print(0::subtract(5)::absolute()) § 5
	Terminal.print(4::isEven()) § true
	Terminal.print(15::clamp(between 1, and 10)) § 10
}
```

`remainder(dividingBy:)` is Euclidean, so it is never negative — `-7 mod 3` is
`2`, which is the answer that makes indexing and cycling work.

## Rationals

A `Rational` is one integer over another, kept in lowest terms with the sign on
the numerator. `3/4` is a literal, not a division that already happened.

```essence
implementation {

	§ A Rational is written as one Integer over another, and is kept in
	§ lowest terms. There is no decimal literal — `0.75` is `3/4`.
	constant threeQuarters = 3/4

	Terminal.print(1/3::add(1/3)::add(1/3)) § 1/1 — exactly one, every time
	Terminal.print(threeQuarters::numerator()) § 3
	Terminal.print(threeQuarters::reciprocal()) § 4/3
	Terminal.print(7/2::round()) § 4 — halves round away from zero
	Terminal.print(2/3::raise(to 2)) § 4/9
}
```

<Note>
	There is no decimal literal. `0.75` does not parse — write `3/4`, or read
	the text with `Rational.parse("0.75")`. Decimals are a rendering of a
	number, and this library keeps them at the edges where rendering happens.
</Note>

`Rational.of(_ numerator, over denominator)` builds one from two computed
integers, which is what you want when the literal form is not available.

## Division that can fail says so

Dividing by zero has no answer, so `divide(by:)` never pretends to have one —
but it also refuses to make you handle a failure that cannot happen. A divisor
the compiler can prove is not zero — a non-zero literal, or a
`NonZeroInteger` it has already checked — gets a plain `Rational`. One it
cannot prove gets an `Optional<Rational>`, and the empty case has to be
handled before the result can be used.

```essence
implementation {

	§ A divisor the compiler can see is not zero — here, a literal — makes
	§ division just division: a plain Rational, no Optional in sight.
	Terminal.print(10::divide(by 4)) § 5/2

	§ A divisor it cannot vouch for gives an `Optional<Rational>`, and the
	§ empty case has to be handled before the result can be used.
	function ratio(_ numerator: Integer, over divisor: Integer) -> Rational {
		<- match numerator::divide(by divisor) -> Rational {
			case #Value(exact) { <- exact }
			case #Empty { <- 0/1 }
		}
	}

	Terminal.print(ratio(10, over 4)) § 5/2
	Terminal.print(ratio(10, over 0)) § 0/1
}
```

Note the type: dividing two `Integer`s gives a `Rational`, not a truncated
integer. `10 / 4` is `5/2`, and stays `5/2` until something asks it to be
something else.

Dividing by an `Algebraic` can likewise never fail — an irrational is never
zero — so that overload answers a plain number with no `Optional` around it.

## Irrationals

Square roots are exact and symbolic. Perfect squares collapse to whole numbers;
everything else stays as itself.

```essence
implementation {

	§ A square root that is not whole stays exact and symbolic — an
	§ Algebraic, never a rounded decimal. A negative has no real root, so
	§ `squareRoot` answers an Optional.
	Terminal.print(9::squareRoot()::otherwise(0)) § 3
	Terminal.print(2::squareRoot()::otherwise(0)) § √2

	§ π and τ are exact Transcendentals.
	Terminal.print(Number.Pi) § π
	Terminal.print(Number.Tau::divide(by Number.Pi)::otherwise(0/1)) § 2/1
	Terminal.print(Number.Pi::isBetween(3, and 22/7)) § true — the classic enclosure
}
```

`√2::multiply(with √2)` is exactly `2`, not `2.0000000000000004`. Comparing π
against `22/7` is exact and total, because the comparison is symbolic rather
than a race between two approximations.

## `Number`, the whole tower

`Number` is `Integer | Rational | Algebraic | Transcendental` under one name.
Its own namespace defines what only a covering type can: equality and ordering
*across* the members.

```essence
implementation {

	§ `Number` is the whole tower under one name:
	§ `Integer | Rational | Algebraic | Transcendental`.
	constant amount: Number = 3/2

	Terminal.print(amount::toString()) § "3/2"

	§ Equality reaches across the members — 1 and 1/1 are the same Number.
	Terminal.print(1::is(1/1)) § true

	§ The aggregates are exact, and stay in the smallest Type that fits.
	Terminal.print(Number.sum([1, 1/2, 1/2])) § 2
	Terminal.print(Number.product([1/2, 2/3])) § 1/3
	Terminal.print(Number.average([1, 2])::otherwise(0/1)) § 3/2
	Terminal.print([3/2, 1, 1/2]::sort()) § [ 1/2, 1, 3/2 ]
}
```

`Number.sum([1, 1/2, 1/2])` is `2`, an `Integer` — the halves cancelled, and
the result narrowed to the type that fits it. `Number.average` answers an
`Optional`, because an empty list has no average.

## Text, both ways

Reading a number from text can fail, so it answers an `Optional`. Writing one
out cannot, so it does not.

```essence
implementation {

	§ Reading a Number from text can fail, so it answers an Optional.
	Terminal.print(Integer.parse("42")::otherwise(0)) § 42
	Terminal.print(Integer.parse("nope")::otherwise(0)) § 0
	Terminal.print(Rational.parse("0.75")::otherwise(0/1)) § 3/4

	§ And the way back. A Rational prints as a fraction unless asked
	§ otherwise — the format is a Choice, so a typo is a Diagnostic.
	Terminal.print(3/4::toString()) § "3/4"
	Terminal.print(3/4::toString(formatAs #Decimal)) § "0.75"
}
```

`NumberFormat` has exactly two cases, `#Fraction` and `#Decimal`. It is a
choice rather than a string for a reason worth stating: with a string, every
spelling the library did not recognise fell back to the fraction form and
nothing told the caller which words were understood. A misspelt case is a
diagnostic instead.

## What is where

`Integer`, `Rational`, `Algebraic` and `Transcendental` each carry their own
same-kind arithmetic and ordering. `Number` carries the cross-kind ones —
mixed-type comparison, `sum`, `product`, `average`, and the constants `Pi`,
`Tau`, `E` and `GoldenRatio`. A receiver whose type is a single member reaches
its own namespace first, so `1::isLessThan(2)` never walks the cross-kind
table.
