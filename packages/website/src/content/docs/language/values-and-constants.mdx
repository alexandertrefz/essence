There are two ways to bind a name, and the difference between them is smaller
than it looks: a `constant` can never be rebound, a `variable` can — and in
neither case can the value itself be changed.

## Two keywords

```essence
implementation {

	§ A constant is bound once and never again.
	constant greeting = "Hello"

	§ A variable can be rebound — the value it held is still immutable.
	variable count = 0

	count = count::add(1)
	count = count::add(1)

	Terminal.print(greeting) § "Hello"
	Terminal.print(count) § 2
}
```

`count::add(1)` does not change `count`. It answers a new `Integer`, and the
assignment points the name at it. That is true of every method in the language:
all data is immutable, so a method can only ever be a question.

Reach for `constant` first. `variable` is worth the two extra characters only
when a name genuinely has to move.

<Note>
	Assigning to a `constant` is a compile error — `constant-reassignment` — and
	the compiler offers turning it into a `variable` as a Quick Fix.
</Note>

## Types are inferred, and can be written

The type goes after the name. It is optional wherever the initial value already
says what it is, and the editor shows the inferred one as an inlay hint you can
double-click to write out.

```essence
implementation {

	§ The Type is written after the name, and is optional wherever the
	§ initial value already says it.
	constant name: String = "essence"
	constant answer: Integer = 42
	constant ratio: Rational = 3/4
	constant ready: Boolean = true

	§ A List and a Record are literals too.
	constant primes: List<Integer> = [2, 3, 5, 7]
	constant origin: { x: Integer, y: Integer } = { x = 0, y = 0 }

	Terminal.print([name, answer::toString(), ratio::toString(), ready::toString()])
	Terminal.print(primes)
	Terminal.print(origin)
}
```

Write the annotation when it is the point — a value that has to be wider than
its literal, a signature you want fixed against future edits — and leave it off
when it would only repeat what is on the right.

## The literals

<div class="table-scroll">

| Type | Literal | Notes |
| --- | --- | --- |
| `Integer` | `42`, `9_007_199_254_740_991` | Arbitrary size. Underscores are separators. |
| `Rational` | `3/4`, `1/3` | Exact, kept in lowest terms. There is no decimal literal. |
| `String` | `"essence"`, `"hi {name}"` | A `{…}` hole interpolates an expression. |
| `Boolean` | `true`, `false` | |
| `List<T>` | `[1, 2, 3]` | Every item the same type. |
| Record | `{ x = 0, y = 0 }` | Fields bound with `=`. |

</div>

## Unions, `Optional` and `type`

A union type says which shapes a value is allowed to have. `Optional<T>` is a
`choice` with two cases — `#Value`, carrying a `T`, and `#Empty`, carrying
nothing — and `type` gives any shape a name of its own.

```essence
implementation {

	§ A Union says which shapes a value is allowed to have.
	constant amount: Integer | Rational = 1/2

	§ `Optional<T>` is a choice: `#Value` carries the value, `#Empty` is
	§ its absence.
	constant nickname: Optional<String> = #Empty

	§ `type` names a shape so it can be written once.
	type Point = { x: Integer, y: Integer }

	constant here: Point = { x = 3, y = 4 }

	Terminal.print(amount::toString())
	Terminal.print(nickname::otherwise("none"))
	Terminal.print(here)
}
```

There is no `null` and no `undefined`, and no value is silently absent. A thing
that might not be there says so in its type, and the only way through it is
[a match](/docs/language/pattern-matching) — or `otherwise`, which is the
shorthand for a match whose other arm is a fallback.

## Immutability is a global invariant

Because nothing can be changed in place, two names holding the same value can
never disagree about it:

```essence
implementation {

	variable list = [1, 2, 3]

	§ `original` keeps looking at the List it was bound to.
	constant original = list

	list = list::append(4)

	Terminal.print(original) § [ 1, 2, 3 ]
	Terminal.print(list) § [ 1, 2, 3, 4 ]
}
```

This is why the standard library's methods are named in the imperative —
`sort`, `reverse`, `trim` — rather than in the past tense. In a language where
`list::sort()` could mutate, `sorted()` is how an immutable API warns you.
There is no mutating `sort` here to be confused with, so the warning has
nothing to warn about.
