## Matching a value

A match takes a subject — the scrutinee — and one arm per case it can be.
Inside an arm, `@` is that subject, already narrowed to what the case
established.

<CodeWindow
	title="first.es"
	class="code-bare"
	compact
	code={`implementation {

	constant listOfIntegers = [1, 2, 3]

	constant firstOrZero = match listOfIntegers::firstItem() -> Integer {
		case #Value(first) { <- first }
		case #Empty        { <- 0 }
	}

	Terminal.print(firstOrZero) § 1
}`}
/>

`firstItem()` answers an `Optional<Integer>` — a `choice` whose `#Value` case
carries the item and whose `#Empty` case carries nothing. The case matcher
`#Value(first)` is what proves there is an item, and names it in the same
stroke; `#Empty` has nothing to name.

<Note>
	The return type after `->` is required. It is how the compiler proves that
	every arm agrees on what the match produces.
</Note>

A match needs something to take apart, so its subject has to be a union or a
choice. Asking one to branch over a plain `Integer` is refused as
`match-on-non-union` — matching a type with only one possible shape has only
one outcome.

## Exhaustiveness

Leaving a case out is a compile error, not a runtime one. Delete the
`case #Empty` arm above and the compiler names what is missing, and points at
the value that has it:

<div class="error-output">

```
[missing-case]
Error: This Match Expression does not handle every Case
   ╭─┤ first.es:5:25 │
   │
 5 │     constant firstOrZero = match listOfIntegers::firstItem() -> Integer {
   │                                  ─────────────┬─────────────
   │                                               ╰─────────────── this is an Optional<Integer>
   │
   │ Help: Add 'case Optional#Empty', or a 'case _' that covers the rest.
   │
   │ Note: Unhandled: 'Optional#Empty'.
───╯
```

</div>

In an editor that diagnostic carries a Quick Fix which scaffolds an arm for
every case the match does not handle — with empty bodies on purpose, so the
`missing-return` behind each one is the hole left to fill. The reverse is
reported too: an arm that can never match is greyed out as `unreachable-case`,
because it is dead rather than wrong.

`case _` is the arm that covers everything left. It is a real answer when the
remainder genuinely has one — and worth avoiding when it does not, because a
`_` is also what stops the compiler telling you about the case you add next
year.

## Guards and literal cases

A guard narrows an arm further with `where`. A literal case matches one exact
value, and reads best above the type case that would otherwise swallow it.

```essence
implementation {

	§ A guard narrows a Case further. Literal Cases match one exact value,
	§ and read best above the Type Case that would otherwise swallow them.
	function describe(_ count: Integer | String) -> String {
		<- match count -> String {
			case 0 { <- "none" }
			case 1 { <- "exactly one" }
			case Integer where @::isNegative() { <- "less than none?" }
			case Integer { <- "many" }
			case String { <- "not a count at all: {@}" }
		}
	}

	Terminal.print(describe(0)) § "none"
	Terminal.print(describe(7)) § "many"
	Terminal.print(describe("seven")) § "not a count at all: seven"
}
```

Arms are tried in order, and the first that fits wins.

## Matching a record

A record case matches structurally, by the fields it names: `:` requires a
type, `=` requires an exact value. Between them they pick a union apart without
naming any of its members.

```essence
implementation {

	type Click = { x: Integer, y: Integer }
	type KeyPress = { key: String }

	constant input: Click | KeyPress = { x = 0, y = 7 }

	§ A Record Case matches by the fields it names — `:` requires a Type,
	§ `=` requires an exact value.
	Terminal.print(match input -> String {
		case { x = 0, y = 0 } { <- "clicked the origin" }
		case { x = 0, y: Integer } {
			<- "clicked the y axis at "::append(@.y::toString())
		}
		case { x: Integer, y: Integer } { <- "clicked somewhere else" }
		case { key: String } { <- "pressed "::append(@.key) }
	}) § "clicked the y axis at 7"
}
```

## Matching a choice

A `choice` is a closed set of cases, each with a payload of its own. A case is
written with `#`, and inside its arm `@` is that payload.

```essence
implementation {

	§ A Choice is a closed set of Cases, each with its own payload.
	choice Shape {
		Circle { radius: Rational },
		Rectangle { width: Rational, height: Rational },
		Point,
	}

	constant shape: Shape = #Circle({ radius = 1/2 })

	§ A Case is written with `#`, and `@` is the payload inside its body.
	Terminal.print(match shape -> Rational {
		case #Circle { <- @.radius }
		case #Rectangle { <- @.width::multiply(with @.height) }
		case #Point { <- 0/1 }
	}) § 1/2
}
```

Because the set is closed, exhaustiveness here is exact: add a case to the
choice and every match over it that has not been updated fails to compile.

`Optional` is itself a `choice` — the `#Value` and `#Empty` arms in the first
example were this same mechanism. And where `@` is the whole payload, a case
matcher — `case #Value(count)` — binds what the case carries to a name
instead.

## Where matching is allowed

A match is an expression, not a statement, so it goes wherever a value goes.

- As an argument, or anywhere else a value is expected.
- As the value a function answers with — `<- match … { … }`.
- Nested inside another arm, to any depth.

```essence
implementation {

	constant amount: Integer | Rational = 1/2

	§ A match is an Expression, so it stands where an Argument goes …
	Terminal.print(match amount -> String {
		case Integer { <- "a whole number" }
		case Rational { <- "a fraction" }
	})

	§ … it is the value a Function answers with …
	function describe(_ value: Optional<Integer>) -> String {
		<- match value -> String {
			case #Value(item) { <- "the Integer {item}" }
			case #Empty { <- "nothing at all" }
		}
	}

	§ … and it nests inside another arm, to any depth.
	Terminal.print(match amount -> String {
		case Integer { <- describe(#Value(@)) }
		case Rational {
			<- match @::reciprocal() -> String {
				case #Value(flipped) { <- "flips to {flipped}" }
				case #Empty { <- "zero flips to nothing" }
			}
		}
	}) § "flips to 2/1"
}
```
