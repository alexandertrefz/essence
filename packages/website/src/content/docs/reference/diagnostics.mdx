Every error and warning the Essence compiler reports starts with a code in square brackets, such as `[missing-return]`. This page has one entry per code. Each entry gives the severity, a report the compiler printed, and the fix. Where a page teaches the code, the entry links that section. An entry's address is its code: `/docs/reference/diagnostics#missing-return`.

```essence
implementation {
	Terminal.print([3, 1, 2]::firstItem(defaultingTo 0)) § 3
}
```

This program runs and prints `3`. `essence check` still reports a warning about it:

<div class="error-output">

```
[fallback-never-used]
Warning: This 'defaultingTo' Argument can never be read
   ╭─┤ First.es:2:38 │
   │
 2 │     Terminal.print([3, 1, 2]::firstItem(defaultingTo 0)) § 3
   │                                         ───────┬──────  
   │                                                ╰──────── this fallback can never be read
   │ 
   │ Help: Drop the 'defaultingTo' Argument; the call already answers an Integer.
   │ 
   │ Note: Without it the call answers an Integer, which is never empty.
───╯
```

</div>

A report has four parts:

- `[fallback-never-used]` is the code. This page is keyed by it, and so are your editor's Quick Fixes. A Quick Fix is an edit your editor offers on the underlined span.
- `Warning` is the severity. The text after it is the message.
- The box quotes the source. Each label under a line says what the compiler found at that span.
- A `Help` line suggests a fix. A `Note` line states the rule behind the report.

The severity says what happens next:

- **Error**: the program is refused. `essence check` exits with status 1, `essence run` runs nothing, and `essence build` writes nothing. Unlike `tsc`, the compiler never emits JavaScript for a program with an Error.
- **Warning**: the program is valid and runs. `essence check` exits with status 0.
- **Information**: advice that never fails anything. [`lonely-tag`](/docs/reference/diagnostics#lonely-tag) is one.

You cannot silence a code or change its severity. There is no comment like `// @ts-expect-error` or `// eslint-disable-next-line`, and no `essence.json` setting for it.

Where a code has a Quick Fix, its entry gives the title your editor shows. Two entries name a Refactor or a Source Action: the same kind of edit, listed in your editor's Refactor or Source Action menu rather than on the error. The reports below were printed by `essence check`, or by `essence test` for the codes `essence check` does not report. Nine codes have no printed report. The editor alone reports three of them, three come from the bundler or a failure inside the compiler, and ordinary programs do not reach the other three.

## If you typed JavaScript

These twenty-two JavaScript habits cause most first-hour reports, and they are not the whole of what the compiler answers: the [`foreign-syntax`](/docs/reference/diagnostics#foreign-syntax) entry below lists the fifty words it knows by name. Nearly all of them report one of three codes — [`foreign-syntax`](/docs/reference/diagnostics#foreign-syntax) for a habit written as words or punctuation, [`operator-not-supported`](/docs/reference/diagnostics#operator-not-supported) for an operator, and [`method-called-with-dot`](/docs/reference/diagnostics#method-called-with-dot) for a method reached with a `.`. Each habit links its row on [Coming from JavaScript](/docs/getting-started/coming-from-javascript), which quotes the message and gives the Essence spelling.

- [`1 + 2`](/docs/getting-started/coming-from-javascript#typed-plus): [`operator-not-supported`](/docs/reference/diagnostics#operator-not-supported)

- [`1 === 1`](/docs/getting-started/coming-from-javascript#typed-equals): `operator-not-supported`
- [`true && false`](/docs/getting-started/coming-from-javascript#typed-and): `operator-not-supported`
- [`!true`](/docs/getting-started/coming-from-javascript#typed-not): `operator-not-supported`
- [`if (ready) {`](/docs/getting-started/coming-from-javascript#typed-if-parentheses-name): [`syntax-error`](/docs/reference/diagnostics#syntax-error)
- [`items[0]`](/docs/getting-started/coming-from-javascript#typed-index): [`foreign-syntax`](/docs/reference/diagnostics#foreign-syntax)
- [`text.length`](/docs/getting-started/coming-from-javascript#typed-length): [`method-called-with-dot`](/docs/reference/diagnostics#method-called-with-dot)
- [`text.charAt(0)`](/docs/getting-started/coming-from-javascript#typed-charat): [`type-without-members`](/docs/reference/diagnostics#type-without-members)

- [`number` as a type](/docs/getting-started/coming-from-javascript#typed-number-type): [`unknown-type`](/docs/reference/diagnostics#unknown-type)

## Syntax

The parser reports these. A syntax error does not hide the rest of the file: the parser drops the statement it could not read and carries on, and the stages after it check what is left. What a dropped statement declared is not reported as undeclared, and a construct it was written inside is not judged for what is missing from it — one mistake gets one report.

### `syntax-error`

**Error.** The parser expected one thing and found another. The message names both.

<div class="error-output">

```
[syntax-error]
Error: Expected '=' but found '42'.
   ╭─┤ Answer.es:2:18 │
   │
 2 │     constant answer 42
   │                     ─┐  
   │                      ╰── expected '='
───╯
```

</div>

A JavaScript habit the parser recognises is answered by [`foreign-syntax`](/docs/reference/diagnostics#foreign-syntax) or [`operator-not-supported`](/docs/reference/diagnostics#operator-not-supported) instead, which name the habit. What is left here is the parser's guess rather than the fix: `if (ready) {` reports `Expected '{' but found '}'.` Look the line up in the list above. Otherwise, write what the message says was expected.

Taught on: [Programs and values › The shape of a file](/docs/language/programs-and-values#the-shape-of-a-file)

### `unexpected-token`

**Error.** Something follows the end of the program. A stray `}` is the usual cause.

<div class="error-output">

```
[unexpected-token]
Error: Unexpected '}' after the end of the Program
   ╭─┤ Answer.es:4:1 │
   │
 3 │ }
   │ ▲  
   │ ╰── the implementation block ends here
 4 │ }
   │ ▲  
   │ ╰── nothing may follow here
   │ 
   │ Note: A Program is one 'implementation { … }' block, framed by an optional 'import { … }' block above it and an optional 'tests { … }' and 'export { … }' block below it.
───╯
```

</div>

Delete it. A file holds one `implementation { … }` block, with an optional `import { … }` block above it, and optional `export { … }` and `tests { … }` blocks below it, in that order.

Taught on: [Programs and values › The shape of a file](/docs/language/programs-and-values#the-shape-of-a-file)

### `unclosed-string`

**Error.** A string literal runs to the end of the file without its closing `"`. The report points at the opening quote and at the end of the input. Every string can hold a hole, `{ … }`, with an expression in it, so a `{` in a string opens one. A `"` inside the hole does not close the string: JSON written as `"{\"a\": 1}"` reports this code.

<div class="error-output">

```
[unclosed-string]
Error: This String Literal is never closed
   ╭─┤ Greeting.es:3:2 │
   │
 2 │     constant greeting = "Hello
   │                         ▲  
   │                         ╰── opened here
 3 │ }
   │  │ 
   │  ╰─ the input ends here
   │ 
   │ Help: Add the missing '"'.
───╯
```

</div>

A literal may span lines, so a missing `"` has two readings: the string ran on, or the quote that appeared to close it was written to open the next one. Where a string that spans lines closes on the very line the unclosed one opens on, the report names the spanning string instead — the quote missing from the end of its first line is the one mistake that explains the file — and points at the quote that closed it and at the end of the input beside it.

<div class="error-output">

```
[unclosed-string]
Error: This String Literal is never closed
   ╭─┤ Greeting.es:2:22 │
   │
 2 │     constant greeting = "Hello
   │                         ▲  
   │                         ╰── opened here
 3 │     constant name = "Ada"
   │                     ▲  
   │                     ╰── closed by this quote, which reads as the start of another String
   │ 
 6 │ }
   │  │ 
   │  ╰─ and the input ends inside that one
   │ 
   │ Help 1: Add the missing '"' at the end of line 2.
   │ Help 2: Or, if line 2 was meant to carry the lines below it, add it at the end of the input instead.
   │ 
   │ Note 1: A String Literal may span lines, and the line breaks are part of it — so the quote on line 3 closed the one opened on line 2, and the String that quote was written to open is the one that ran to the end of the input.
   │ Note 2: One '"' is missing either way. It is reported against the String that spans lines, because a String written to span them is not usually followed, on the line it closes, by a second one that never closes at all.
───╯
```

</div>

Add the closing `"`. For a literal brace, write `\{` and `\}`: `"\{\"a\": 1\}"` prints `{"a": 1}`.

Quick Fix: **Add the missing '"'**.

Taught on: [Programs and values › Strings](/docs/language/programs-and-values#strings)

### `unclosed-block`

**Error.** A `{` is never closed. Where a `}` below the mistake is written further out than the brace it was meant for, the report is about the block that lost its brace: it points at that block's `{`, and at the `}` that closed it instead.

<div class="error-output">

```
[unclosed-block]
Error: This block is never closed
   ╭─┤ Greeting.es:2:43 │
   │
 2 │     function greet(_ name: String) -> String {
   │                                              ▲  
   │                                              ╰── this block is never closed
   │ 
 4 │ }
   │ ▲  
   │ ╰── this '}' is written further out, so it closes the block around it
   │ 
   │ Help: Write the '}' where this block's Statements end.
   │ 
   │ Note: Which block a '}' closes is counted rather than read off the indentation, so a file one brace short hands every '}' below the mistake to the block above the one it was written for — and the end of the input is where that is noticed.
───╯
```

</div>

Here the function has no `}` of its own, so the file's last `}` closes the function, and `implementation` is the block left open. Write a `}` after `<- name`.

Where no `}` stands further out than its opener — a file that simply ends one brace short — there is no second brace to point at, so the report names the outermost open block and the end of the input:

<div class="error-output">

```
[unclosed-block]
Error: This block is never closed
   ╭─┤ Greeting.es:2:29 │
   │
 1 │ implementation {
   │                ▲  
   │                ╰── opened here
 2 │     constant greeting = "Hello"
   │                                │ 
   │                                ╰─ the input ends here
   │ 
   │ Help: Add the missing '}'.
───╯
```

</div>

Close every open block.

### `invalid-number`

**Error.** A number literal holds something other than digits. Essence has no hexadecimal, binary or exponent form. A trailing `;` is answered by [`foreign-syntax`](/docs/reference/diagnostics#foreign-syntax) instead.

<div class="error-output">

```
[invalid-number]
Error: '0xFF' is not a valid Number
   ╭─┤ Mask.es:2:18 │
   │
 2 │     constant mask = 0xFF
   │                     ──┬─  
   │                       ╰─── this is not a Number
   │ 
   │ Help: Essence has no hexadecimal, binary or exponent form; write the value in digits.
   │ 
   │ Note: A Number is written in the digits '0' through '9', grouped with '_' where that helps, with a fractional part written behind a '.' — 1_000_000, 19.99.
───╯
```

</div>

Write the value in the digits `0` to `9`, such as `255` for `0xFF`. Group digits with `_` and write a fraction part after a `.`. Delete a trailing `;`.

Taught on: [Programs and values › Integers](/docs/language/programs-and-values#integers)

### `mixed-rational-literal`

**Error.** A rational literal is written as a fraction and a decimal at once, such as `1.5/2`.

<div class="error-output">

```
[mixed-rational-literal]
Error: A Rational Literal is a fraction or a decimal, not both
   ╭─┤ Half.es:2:19 │
   │
 2 │     constant ratio = 1.5/2
   │                      ──┬──  
   │                        ╰──── '/' can not follow a decimal
   │ 
   │ Help: Write the fraction — '3/4' — or the decimal — '0.75'.
   │ 
   │ Note: A fraction and a decimal are two spellings of one Rational — '3/4' and '0.75' are the same value — so a Literal written both ways says the same thing twice, and leaves it to the reader which parts belong to which.
───╯
```

</div>

Write one spelling: `3/4` or `0.75`. Both are the same exact `Rational`, and both print as `3/4`.

Quick Fix: **Write it as '3/4'** or **Write it as '0.75'**, each writing the value in one spelling.

Taught on: [Programs and values › Rationals](/docs/language/programs-and-values#rationals)

### `partial-decimal-literal`

**Error.** A decimal literal has nothing on one side of its point, such as `.5` or `1.`.

<div class="error-output">

```
[partial-decimal-literal]
Error: A decimal Literal has digits on both sides of the dot
   ╭─┤ Half.es:2:18 │
   │
 2 │     constant half = .5
   │                     ─┐  
   │                      ╰── nothing stands before the point
   │ 
   │ Help: Write the digits before the point: '0.5'.
   │ 
   │ Note: A '.' that opens an Expression is a member path — '.price' reads a member off the value it is handed — and digits can not name a member, so this is a decimal missing its whole part rather than a path.
───╯
```

</div>

Write digits on both sides: `0.5`, `1.0`. Drop the point instead when you meant a whole number: `1`.

Quick Fix: **Write it as '0.5'**. A trailing point is offered both `1.0` and `1`.

Taught on: [Programs and values › Rationals](/docs/language/programs-and-values#rationals)

### `invalid-escape`

**Error.** A backslash in a string is followed by a character that is not an escape. The escapes are `\"`, `\\`, `\n`, `\r`, `\t`, `\{` and `\}`. `\{` and `\}` write a brace, because every string can hold `{ … }` holes, not only a template literal.

<div class="error-output">

```
[invalid-escape]
Error: '\d' is not a valid escape
   ╭─┤ Path.es:2:23 │
   │
 2 │     constant folder = "C:\data"
   │                          ─┐  
   │                           ╰── this escape is not known
   │ 
   │ Help: Write '\\' for a literal backslash, or drop the backslash to keep the character as itself.
   │ 
   │ Note: A String understands '\"', '\\', '\n', '\r', '\t', '\{' and '\}'; every other backslash is an error.
───╯
```

</div>

Write `\\` for a backslash: `"C:\\data"` prints `C:\data`. Drop the backslash if it was a typo.

Quick Fix: **Write '\\\\' for a literal backslash** or **Drop the backslash**.

Taught on: [Programs and values › Strings](/docs/language/programs-and-values#strings)

### `comment-in-hole`

**Error.** A `§` comment is written inside a string's `{ … }` hole. A comment runs to the end of its line, so it would swallow the hole's `}` and the closing `"`.

<div class="error-output">

```
[comment-in-hole]
Error: A Comment can not be written inside an interpolation hole
   ╭─┤ Label.es:2:33 │
   │
 2 │     constant label = "answer: { 42 § the answer }"
   │                                    ──────┬──────  
   │                                          ╰──────── this Comment would swallow the rest of the String
   │ 
   │ Help: Move the Comment out of the String — behind the closing '"' works.
   │ 
   │ Note: A Comment runs to the end of its line — inside a hole it would take the hole's '}' and the String's closing '"' with it.
───╯
```

</div>

Move the comment out of the string, for example behind the closing quote: `constant label = "answer: { 42 }" § the answer`.

Taught on: [Programs and values › Comments](/docs/language/programs-and-values#comments)

### `nesting-too-deep`

**Error.** Code nests 1,024 levels deep at one point, for example 1,024 lists inside each other. The parser stops at that depth with this error.

Name the inner values as constants, or the inner types as type aliases, so that no single expression nests that deep.

### `redundant-parameter-label`

**Error.** A parameter of a function literal has two names and no type, such as `(each number)`. A parameter without a type takes its label from the function type it is passed to.

<div class="error-output">

```
[redundant-parameter-label]
Error: A Parameter without a Type can not carry a label
   ╭─┤ Double.es:2:37 │
   │
 2 │     constant doubled = [1, 2, 3]::map((each number) { <- number::multiply(with 2) })
   │                                        ─────┬─────  
   │                                             ╰─────── two names, no Type
   │ 
   │ Help: Write only 'number'.
   │ 
   │ Note: Such a Parameter takes its label from the expected Function Type.
───╯
```

</div>

Write only the name: `[1, 2, 3]::map((number) { <- number::multiply(with 2) })`.

Quick Fix: **Remove the label**.

Taught on: [Functions as values › Writing some of a literal's types](/docs/language/functions-as-values#writing-some-of-a-literals-types)

### `reserved-parameter-label`

**Error.** A parameter's label is spelled `start` or `complete`. Both words open an [expression](/docs/language/asynchrony#two-words-that-are-also-names) where a label would stand, so `compute(start 1)` is a `start` of `1` and never an argument labelled `start` — a parameter asking for that label could not be written at a call at all.

<div class="error-output">

```
[reserved-parameter-label]
Error: A Parameter's label can not be spelled 'start'
   ╭─┤ Compute.es:2:19 │
   │
 2 │     function compute(start value: Integer) -> Integer {
   │                      ──┬──  
   │                        ╰──── this word opens an Expression
   │ 
   │ Help 1: Name the label another word.
   │ Help 2: Or write '_' in its place, so the Parameter takes no label at all.
   │ 
   │ Note: An Argument written 'start value' reads as a 'start' of the value, so no call could pass this Parameter by name.
───╯
```

</div>

Name the label another word, or write `_` in its place so the parameter takes none: `function compute(_ value: Integer)`.

Taught on: [Asynchrony › Two words that are also names](/docs/language/asynchrony#two-words-that-are-also-names)

### `shorthand-in-combination`

**Error.** An update's key list holds a bare name, as in `{ base with port, host }`. The shorthand `{ port }` belongs to a record literal. JavaScript's `{ ...base, port }` sets `port` from a variable of that name, but after `with` a bare name is a whole record to merge in.

<div class="error-output">

```
[shorthand-in-combination]
Error: A bare member name is not a key in an update
   ╭─┤ Server.es:5:32 │
   │
 5 │     constant server = { base with port, host }
   │                                   ──┬─  
   │                                     ╰─── this names no value to set
   │ 
   │ Help 1: Write 'port = port'.
   │ Help 2: Or merge a whole Record: '{ base with { port } }'.
   │ 
   │ Note: An update's key list always spells its values, because a bare name after 'with' is already the value being merged in.
───╯
```

</div>

Write each value, `{ base with port = port, host = host }`, or merge a record literal that uses the shorthand: `{ base with { port, host } }`.

Quick Fix: **Write 'port = port'**.

Taught on: [Records › When the compiler refuses a record](/docs/language/records#when-the-compiler-refuses-a-record)

### `dictionary-entry-syntax`

**Error.** A dictionary entry uses a separator other than `=`, such as `["kim": 7]`.

<div class="error-output">

```
[dictionary-entry-syntax]
Error: A Dictionary entry is written with '='
   ╭─┤ Ages.es:2:24 │
   │
 2 │     constant ages = ["kim": 7]
   │                           ▲  
   │                           ╰── expected '=' and found ':'
   │ 
   │ Help: Write '=' in place of ':'.
   │ 
   │ Note: An entry is 'key = value', and a Dictionary is a bracket list of them: '["a" = 1, "b" = 2]'.
───╯
```

</div>

Write each entry as `key = value`: `["kim" = 7]`.

Taught on: [Dictionaries › Writing a dictionary](/docs/language/dictionaries#writing-a-dictionary)

### `shorthand-on-path-key`

**Error.** A dotted key in an update's key list has no value, as in `{ config with server.port, name = "cache" }`. A path is not a name in scope, so it cannot stand for its own value.

<div class="error-output">

```
[shorthand-on-path-key]
Error: A path key names no binding
   ╭─┤ Config.es:4:33 │
   │
 4 │     constant moved = { config with server.port, name = "cache" }
   │                                    ─────┬─────  
   │                                         ╰─────── this reaches into a value to set
   │ 
   │ Help: Write 'server.port = port'.
   │ 
   │ Note: A bare name is a member and its own value; a path is neither, because the value it would set is not the name it reaches through.
───╯
```

</div>

Write the value: `{ config with server.port = port, name = "cache" }`.

Quick Fix: **Write 'server.port = port'**.

### `empty-path-group`

**Error.** The braces after a path key are empty, as in `{ config with server.{ } }`.

<div class="error-output">

```
[empty-path-group]
Error: This descend updates nothing
   ╭─┤ Config.es:3:32 │
   │
 3 │     constant same = { config with server.{ } }
   │                                   ─────┬────  
   │                                        ╰────── no member is written here
   │ 
   │ Help: Write the members to update inside it, or drop the key.
   │ 
   │ Note: An update writes the members it names, so a descend with none in it says to leave 'server' exactly as it is.
───╯
```

</div>

Write the members to change inside the braces, `{ config with server.{ port = 8080 } }`, or remove the key.

Taught on: [Records › When the compiler refuses a record](/docs/language/records#when-the-compiler-refuses-a-record)

### `path-is-members-only`

**Error.** A member path such as `.price` is followed by `::` or `(`. A path reads members and cannot carry a call.

<div class="error-output">

```
[path-is-members-only]
Error: A member path reads members and nothing else
   ╭─┤ Prices.es:2:47 │
   │
 2 │     constant labels = [{ price = 3 }]::map(.price::toString())
   │                                                  ▲  
   │                                                  ╰── '::' can not follow a path
   │ 
   │ Help: Write the Function literal instead: '(_ item: SomeType) { <- item.price::rounded() }'.
   │ 
   │ Note: A path is the Function that reads those members off its Argument, so there is nothing here for a call to be made on.
───╯
```

</div>

Write a function literal instead: `[{ price = 3 }]::map((item) { <- item.price::toString() })`.

Taught on: [Functions as values › Member paths](/docs/language/functions-as-values#member-paths)

### `default-on-function-literal`

**Error.** A parameter of a function literal has a default value. A literal is called through its function type, which fixes how many arguments every call passes, so the default could never apply.

<div class="error-output">

```
[default-on-function-literal]
Error: A Function literal can not carry a default
   ╭─┤ Double.es:2:41 │
   │
 2 │     constant double = (_ number: Integer = 1) -> Integer { <- number::multiply(with 2) }
   │                                            ▲  
   │                                            ╰── this default
   │ 
   │ Help: Write the default on the named Function or Method this value is passed to.
   │ 
   │ Note: A Function literal is called through the Function Type it was written for, which fixes how many Arguments every call passes, so a default here could never be reached.
───╯
```

</div>

Remove the default. Write it on the named function or method the literal is passed to.

Quick Fix: **Remove the default**.

### `foreign-syntax`

**Error.** The line is written in another language. The message names the habit and the note names the Essence spelling. Every row of [Coming from JavaScript](/docs/getting-started/coming-from-javascript) that reports this one gives the rewritten line.

<div class="error-output">

```
[foreign-syntax]
Error: 'const' is not how Essence declares a binding
   ╭─┤ Total.es:2:2 │
   │
 2 │     const total = 1
   │     ──┬──  
   │       ╰──── Essence writes 'constant' here
   │ 
   │ Help: Write 'constant' in place of 'const'.
   │ 
   │ Note: A binding is declared with 'constant', or with 'variable' where it is reassigned; there is no third form.
───╯
```

</div>

One code covers the family, and the message says which habit was written. It answers fifty words, and thirteen habits written in punctuation, quotes or brackets.

The punctuation: a `;` at the end of a statement; `{ x: 1 }` for a record member; `point.x = 2`; `(n) => n`; `c ? a : b`; `// a comment` and `/* a comment */`; `'hi'` and `` `hi` `` for a string; `identity<Integer>(1)`; `primes[0]` and `ages["ada"]` for an item read by position or key, and `primes[0] = 5` for one written by position; and `user!` and `user?.name`.

The words: `const`, `let`, `var`, `mut` and `return`; `null`, `undefined`, `nil`, `None` and `Some`; `this` and `self`; `print`, `println`, `println!`, `puts`, `echo` and `fmt`; `len`, `console`, `Math`, `parseInt`, `parseFloat`, `NaN` and `Infinity`; `new`, `class`, `def`, `fn` and `func`; `elif`, `guard`, `switch`, `typeof` and `instanceof`; `throw`, `try` and `catch`; `while`, `break` and `continue`; `enum`, `interface`, `implements` and `extends`; `async` and `await`; and `Map`, `Set` and `require`.

A declaration keyword is reported once and read on: `const price = 12` declares `price` for the rest of the file, so one mistake is one report rather than one per line that reads it. An index recovers the same way, and has to: `constant first = primes[0]` keeps `first` declared, bound to an error rather than to the list in front of the brackets, so neither the name nor its type is reported about again.

An index with an `=` behind it is a write, and is answered about writing: `primes[0] = 5` gets `A value is not written into with brackets`, the methods that rebuild a list and a dictionary — `primes = primes::replace(5, at 0)`, `ages = ages::set("ada", to 37)` — and the whole statement, since nothing changes a collection in place. That one is refused rather than read on: what follows the `=` is the value being stored, and reading on would answer it as a statement of its own.

An index is refused by its spacing. A `[` written flush against the value in front of it is an index; one written a space behind a name is the list that name labels, as in `append(contentsOf [4])`. That is the rule `#` and `.` are already read by — see [A label sits in front of its value](/docs/reference/syntax-glossary#labels-flush).

Quick Fix: **Write 'constant' instead of 'const'**, and its equivalent wherever one word replaces one word. There is none where the fix is a restructuring — a `=>` body, a ternary, a member assignment.

Taught on: [Coming from JavaScript](/docs/getting-started/coming-from-javascript)

## Types

A value or call that does not fit its type, a function that does not return, and a type written in a way the compiler refuses.

### `assignment-type-mismatch`

**Error.** A value does not fit the declared type of the constant or variable it is assigned to. The report also points at the declaration when it is in the same file.

<div class="error-output">

```
[assignment-type-mismatch]
Error: This value does not fit Variable 'count'
   ╭─┤ Count.es:4:10 │
   │
 2 │     variable count = 0
   │              ──┬──  
   │                ╰──── declared as Integer here
   │ 
 4 │     count = "ten"
   │             ──┬──  
   │               ╰──── this is a String
───╯
```

</div>

Assign a value of the declared type, or change the declaration's type.

Asynchrony adds three Helps under this code. A [`Future`](/docs/library/future) standing where its value is wanted asks for `complete`, and so does a `Started`, which is still in flight; the Quick Fix **Wait for it with 'complete'** writes the word for either. A plain value where a future is wanted asks for one to be built — `Async.deferred(…)`, [`map`](/docs/library/future#map) or [`andThen`](/docs/library/future#andThen).

A variable declared from an empty `[]` or `[=]` carries a slot nothing has decided, and a write that would leave it undecided is refused rather than let through. A value that _can_ decide the slot always does, so what reaches this report is a write that cannot — and `List<Unknown>` on the expected side is a blank, not a type. That is what the Note and Help are there to say: the Note explains the label, and the Help spells the annotation that would decide the blank at the depth it sits — `'variable rows: List<List<Integer>>'` for a variable declared as `[[]]`, `'variable box: { items: List<Integer> }'` where the blank is a record's member, `'variable x: List<Integer> | String'` where it is one arm of a union.

The same pair is added wherever else a blank can be the expected side: [`partial-type-mismatch`](#partial-type-mismatch) for a record update, [`return-type-mismatch`](#return-type-mismatch) for a `<-` or a `define` arm inside a function literal whose return type was inferred, and [`payload-type-mismatch`](#payload-type-mismatch) for a case built from a generic choice applied to one. They are said only about the blank that did the refusing: a type can hold a blank the refused value never met, and nothing is said about that one.

Taught on: [Programs and values › Constants and variables](/docs/language/programs-and-values#constants-and-variables)

### `no-matching-overload`

**Error.** The arguments fit none of a method's overloads. The labels name the argument the closest candidate refused, what it is, and what that candidate takes there; each candidate signature is listed in a Note, with where it first disagreed where that is somewhere else.

<div class="error-output">

```
[no-matching-overload]
Error: No overload of 'add' accepts these Arguments
   ╭─┤ Add.es:2:17 │
   │
 2 │     Terminal.print(5::add("one"))
   │                       ─┬─ ──┬──  
   │                        ╰────│──── 'Integer::add' takes an Integer as Parameter 1
   │                             │    
   │                             ╰──── this is a String
   │ 
   │ Note 1: 'Integer::add' takes 1 Argument: Parameter 1 is Integer.
   │ Note 2: 'Integer::add' takes 1 Argument: Parameter 1 is Rational.
   │ Note 3: 'Integer::add' takes 1 Argument: Parameter 1 is Algebraic.
   │ Note 4: 'Integer::add' takes 1 Argument: Parameter 1 is Transcendental.
   │ Note 5: 'NonNegativeInteger::add' takes 1 Argument: Parameter 1 is PositiveInteger.

</div>

Pass arguments that one of the listed signatures takes: `5::add(1)`.

Quick Fix: **Wait for it with 'complete'**, for that argument alone. Nothing is offered for any other refusal: what to pass instead is a judgement.

### `unknown-method`

**Error.** No namespace in scope declares a method of that name for the value's type. The Note lists the namespaces it searched.

<div class="error-output">

```
[unknown-method]
Error: No Method named 'shout' for this value
   ╭─┤ Shout.es:2:26 │
   │
 2 │     Terminal.print("hello"::shout())
   │                    ───┬───  ──┬──  
   │                       ╰───────│──── this is a NonEmptyString
   │                               │    
   │                               ╰──── no Method of this name
   │ 
   │ Note: Searched Namespaces 'String', 'NonEmptyString'.
───╯
```

</div>

Fix the spelling, declare the method in a namespace, or import the namespace that has it.

When the value **holds** something that does have the method, the report says so instead of guessing at a near miss. A list holds its items, a dictionary its values, a case its payload, and a [future](/docs/language/asynchrony) the value it answers with:

<div class="error-output">

```
[unknown-method]
Error: No Method named 'add' for this value
   ╭─┤ Totals.es:4:25 │
   │
 4 │     Terminal.print(prices::add(1)::toString())
   │                    ───┬──  ─┬─  
   │                       ╰─────│─── this is a List<Integer>
   │                             │   
   │                             ╰─── no Method of this name
   │ 
   │ Help 1: Call '::add(…)' on each item — '::map((item) { <- item::add(…) })'.
   │ Help 2: Or read one out with '::item(at …, defaultingTo …)' and call '::add(…)' on it.
   │ 
   │ Note 1: 'add' is a Method of Integer, which is what a List<Integer> holds — a Method of its items rather than of the List itself.
   │ Note 2: Searched Namespaces 'List', 'IntegerList', 'NumberList', 'KeyedNumberList', 'GroupedList'.
───╯
```

</div>

The reading method in the second Help is read off the receiver, so a [`NonEmptyList`](/docs/library/list#NonEmptyList) is offered `firstItem()` — which answers the item outright — and a plain list is offered `item(at:defaultingTo:)` instead. A [`Dictionary`](/docs/library/dictionary) gets no `::map` Help at all, because its transform is handed a whole `{ key, value }` entry rather than the value on its own.

A forgotten [`complete`](/docs/language/asynchrony) is the same mistake with a different answer. `complete` takes the whole call chain behind it, so the word cannot go in front of the call that was refused, and the Help binds the value first:

<div class="error-output">

```
[unknown-method]
Error: No Method named 'add' for this value
   ╭─┤ Report.es:8:28 │
   │
 8 │     Terminal.print(fetched()::add(1)::toString())
   │                    ────┬────  ─┬─  
   │                        ╰───────│─── this is a Future<Integer>
   │                                │   
   │                                ╰─── no Method of this name
   │ 
   │ Help 1: Wait for it on a line of its own — 'constant answered = complete …' — and call '::add(…)' on 'answered'.
   │ Help 2: Or reach through it with '::map((value) { <- value::add(…) })', which answers another Future.
   │ 
   │ Note 1: 'add' is a Method of Integer. This describes work that has not run — the Integer is what a Future<Integer> answers with, once something waits for it.
   │ Note 2: 'complete' takes the whole chain behind it, so a 'complete' written in front of this call would wait for the call rather than for the receiver.
   │ Note 3: Searched Namespace 'Future'.
───╯
```

</div>

Written where nothing can wait — inside a body that answers something other than a future — the Help naming the word is withheld, because following it would be refused. A `Started` reads the same, with "This is still in flight" in place of the first sentence.

On a union receiver the Note also says which members answer the name: `'uppercase' answers for String, and not for Integer.`

A near miss is drawn first from the methods whose call this call could have been — the ones whose labels and argument count fit what was written — so a name that would only trade this refusal for the next is not offered. Where none of those is close and the call wrote a label, every method name is measured again, one edit at most: `primes::lenght(of 1)` is answered `Did you mean 'length'?`, because the label is a second mistake rather than a reason to say nothing about the name.

Quick Fix: **Change to 'name'** when a method name is close, or an import of a namespace another module exports. No spelling fix is offered where the value holds the answer: the name is not what went wrong.

Taught on: [Method calls › When a call fails](/docs/language/method-calls#when-a-call-fails)

### `unknown-case`

**Error.** No case of that name exists where one was looked for. That place is a named choice, the matched value's type, the choice the position expects, or, for a bare `#Case` nothing decides, every choice in scope.

Where the position decides a choice — an annotation, a return type, a parameter a direct argument is passed to, a `match` over a known subject — the report names that choice and lists the cases it declares. Every mode in the standard library is a bare case at a parameter, so this is how you discover what [`round(toward:)`](/docs/library/rational#round) or [`trim(at:)`](/docs/library/string#trim) will take:

<div class="error-output">

```
[unknown-case]
Error: 'Colour' declares no Case '#Purple'
   ╭─┤ Colour.es:8:29 │
   │
 8 │     constant colour: Colour = #Purple
   │                                ───┬──  
   │                                   ╰──── no such Case
   │ 
   │ Note: This position takes a Colour: '#Red', '#Green', '#Blue'.
───╯
```

</div>

A case that carries a payload is listed with it — `'#Value(item)'` — so the note is a list you can write from, and a long list stops at eight with "and N more". A case carries one value, so a payload of several members is listed as the [record](/docs/language/records) it is: `'#Rect({ width, height })'`, which is what you write where the list stands. An [overload](/docs/reference/syntax-glossary#overload) whose candidates accept different choices gets one note each, and the message names none of them.

Where nothing decides the choice, the message is "No Choice in scope declares a Case '#Purple'", a note names the choices that declare the nearest case name, and the Help says to annotate the value so that a choice has a say. A `match` written on a value that *holds* the choice — a [future](/docs/language/asynchrony) answering one — is told so, and told to wait for it first.

Fix the case name.

Quick Fix: **Change to '#Red'** when a case name is close. The near miss is drawn from the position's own choice where there is one, so it is always a case that would resolve.

Taught on: [Choices and `match` › Building a case](/docs/language/choices-and-match#building-a-case)

### `uninferable-type-parameter`

**Error.** The compiler cannot infer a function's type parameter at a call, because no argument gives it the type. A function with no parameters, such as `empty<infer Item>() -> List<Item>`, reports it when called as `empty()`.

<div class="error-output">

   │                         ╰───── nothing here determines what it binds to
   │ 
   │ Help 1: Give the Type Parameter a place among the Parameters, so that an Argument binds it.

### `interpolation-not-printable`

**Error.** A `{ … }` hole in a string holds a value that does not conform to `Printable`. A union does not take `Printable` from its members, so `Integer | String` is not `Printable` although both members are. A union of number types is the exception.

<div class="error-output">

   │ 
   │ Note: Integer | String does not conform to 'Printable'.
───╯
```

</div>

A hole holding a [future](/docs/language/asynchrony) is a forgotten `complete` rather than a printing problem, and the report says so in the words every other missing-`complete` report uses:

<div class="error-output">

   │                                  ╰────── this is Future<Integer>, which is not Printable

   │
   │ Note 1: Future<Integer> does not conform to 'Printable'.
   │ Note 2: Integer is what a Future<Integer> answers with, once something waits for it.
───╯
```

</div>

 3 │        constant answered = complete Async.deferred(() { <- url })
   │                            ───────────────────┬──────────────────  
   │                                               ╰──────────────────── this Function returns String
   │ 
   │ Help: Declare the return Type 'Future<String>'.
   │ 
   │ Note: A body that writes 'complete' suspends, so it hands back a Future the caller completes in its turn — which is what its declared Type has to say.
───╯
```

</div>

Declare the return type a future of what the body answers with. The positions that can not suspend are a parameter's default, a test's name, a `benchmark` body and a property body, `test … for any (…)`; each reports the same code, under one label that says the position can not suspend, and the Note names all four. There the fix is to complete the work above the position, into a constant it reads.

Quick Fix: **Declare the return Type 'Future\<String\>'**, wrapping the return type the body already declares. It is offered on a `complete` in a body, and not in a parameter's default, where wrapping that function's return type would leave the default exactly as wrong.

Taught on: [Asynchrony › A body that waits](/docs/language/asynchrony#a-body-that-waits)

### `unused-future`

**Error.** A statement is a future. Building one runs nothing, so a description nobody starts and nobody waits for does nothing at all.

<div class="error-output">

```
[unused-future]
Error: Nothing here runs
   ╭─┤ Report.es:8:2 │
   │
 8 │     delayed("a")
   │     ──────┬─────  
   │           ╰─────── this is a Future<String>, and its value goes nowhere
   │ 
   │ Help 1: Did you mean 'complete', to wait for it — or 'start', to put it in flight and carry on?
   │ Help 2: Or, where the call was written for what it does rather than for what it answers, hold its answer in a Constant.
   │ 
   │ Note: A Future describes work. Building one runs none of it — 'start' puts it in flight and 'complete' waits for what it answers with.
───╯
```

</div>

Write `complete` in front of it to wait for it, or `start` to put it in flight and carry on.

Where the statement is a call written for what it *does* — `Terminal.inspect(work)` prints, and answers with what it was handed — neither keyword is the edit. Hold the answer in a constant.

Quick Fix: **Wait for it with 'complete'** and **Put it in flight with 'start'**. Neither is preferred over the other: both are whole things to mean, and the line does not say which.

Taught on: [Asynchrony › One run, read many times](/docs/language/asynchrony#one-run-read-many-times)

### `unobserved-started`

**Information.** A statement is a started run. It does run — what nobody does is read what it answers with. Fire and forget is allowed, and this says so once.

<div class="error-output">

```
[unobserved-started]
Advice: Nothing waits for this
    ╭─┤ Report.es:27:2 │
    │
 27 │     start headline()
    │     ────────┬───────  
    │             ╰───────── this runs, and nobody reads its answer
    │ 
    │ Help: Hold it in a Constant and 'complete' it where the answer is wanted, if the answer is wanted at all.
    │ 
    │ Note: A Started can be completed any number of times, from anywhere — holding it under a name is what makes that possible later.
────╯
```

</div>

Leave it where the answer is genuinely not wanted. Otherwise hold the run in a constant and `complete` it where the answer is.

The label says which statement it is. A `start` reads `this runs, and nobody reads its answer`; a call that merely answered with a run reads `this answers a run, and nobody reads what it answers with`.

Inside a `test` body, fire and forget lasts as long as the test does: a test runs under a context of its own, and stopping a run stops everything it started, so work the test walked away from is stopped when the test ends. It can not print into the next test's report, and it can not hold `essence test` open.

There is no Quick Fix. Both answers are things only you know: leaving it is no edit at all, and holding it in a constant needs a name for the work.

Taught on: [Asynchrony › One run, read many times](/docs/language/asynchrony#one-run-read-many-times)

### `needless-complete`

**Warning.** The value after `complete` is neither a `Future` nor a `Started`, so it is already the answer. The span is greyed out rather than underlined.

<div class="error-output">

```
[needless-complete]
Warning: This is not work to wait for
   ╭─┤ Waited.es:2:20 │
   │
 2 │     constant waited = complete 3
   │                                ▲  
   │                                ╰── this is an Integer
   │ 
   │ Help: Drop the 'complete'.
   │ 
   │ Note: 'complete' waits for what a Future or a Started answers with — a value that is neither is already the answer.
───╯
```

</div>

Drop the word.

Quick Fix: **Drop the 'complete'**.

Taught on: [Asynchrony › A body that waits](/docs/language/asynchrony#a-body-that-waits)

### `needless-start`

**Warning.** The value after `start` is not a `Future`, so it describes no work to put in flight.

<div class="error-output">

```
[needless-start]
Warning: This is not a Future, so there is nothing to start
   ╭─┤ Running.es:2:21 │
   │
 2 │     constant running = start 4
   │                              ▲  
   │                              ╰── this is an Integer
   │ 
   │ Help: Drop the 'start'.
   │ 
   │ Note: 'start' puts a Future in flight and answers the one run of it — a value that is not a Future describes no work to run.
───╯
```

</div>

Drop the word. A `Started` reports the same code with a message of its own, `This is already in flight`: the run belongs to whoever started it, and there is no second run to ask for.

Quick Fix: **Drop the 'start'**.

Taught on: [Asynchrony › One run, read many times](/docs/language/asynchrony#one-run-read-many-times)

## The project file

Mistakes in `essence.json`. Each is a Warning: the setting falls back to its default and the run goes on. `essence build`, `run`, `watch`, `test` and `init` report them at the head of a run; `essence check` does not.

### `unknown-setting`

**Warning.** `essence.json` has a key that is not a setting. The Note lists the settings at that level. Nothing is read from the key.

<div class="error-output">

```
[unknown-setting]
Warning: "exclusions" is not a setting
   ╭─┤ essence.json:2:2 │
   │
 2 │     "exclusions": ["build"]
   │     ──────┬─────  
   │           ╰─────── not a setting
   │ 
   │ Note 1: The settings at the top of essence.json are "$schema", "exclude", "test", "build".
   │ Note 2: Nothing was read from this key.
───╯
```

</div>

Fix the key's spelling.

Quick Fix: **Change to "exclude"** when the key is a near miss.

Taught on: [essence.json › Mistakes are Warnings](/docs/reference/project-file#mistakes-are-warnings)

### `setting-shape`

**Warning.** A setting has a value of the wrong shape, such as a string where a list of tags belongs.

<div class="error-output">

```
[setting-shape]
Warning: "test.skipTags" is not a list of tag names
   ╭─┤ essence.json:3:15 │
   │
 3 │        "skipTags": "slow"
   │                    ───┬──  
   │                       ╰──── written as a String
   │ 
   │ Help: Write it as a list of tag names: ["slow"]
   │ 
   │ Note: No tag is skipped by default.
───╯
```

</div>

Write the shape the Help shows: `"skipTags": ["slow"]`.

Taught on: [essence.json › Mistakes are Warnings](/docs/reference/project-file#mistakes-are-warnings)

### `moved-setting`

**Warning.** A key is written where its setting used to be read. `test.exclude` is now the top-level `exclude`.

<div class="error-output">

```
[moved-setting]
Warning: "test.exclude" has moved to "exclude"
   ╭─┤ essence.json:3:3 │
   │
 3 │        "exclude": ["fixtures"]
   │        ────┬────  
   │            ╰────── no longer read here
   │ 
   │ Help: Move it: "exclude": ["fixtures"]
   │ 
   │ Note 1: "exclude" keeps the editor out of those directories as well as the test walk, so it sits at the top rather than under "test".
   │ Note 2: Nothing was read from this key.
───╯
```

</div>

Move it to the top of the file: `"exclude": ["fixtures"]`.

Quick Fix: **Move it to "exclude"**.

Taught on: [essence.json › Mistakes are Warnings](/docs/reference/project-file#mistakes-are-warnings)

### `unreadable-project-file`

**Warning.** `essence.json` does not parse. It is JSON with comments and trailing commas allowed. Every setting stays at its default until the file parses.

<div class="error-output">

```
[unreadable-project-file]
Warning: essence.json could not be read as JSON
   ╭─┤ essence.json:2:1 │
   │
 2 │     "exclude": ["build"
   │ ▲───

   │ 
   │ Help: The file is JSON with comments and trailing commas allowed, as tsconfig.json is.
   │

```

</div>

Taught on: [essence.json › Mistakes are Warnings](/docs/reference/project-file#mistakes-are-warnings)

## The compiler as a program

Problems with the run itself rather than with a program. These reports have no source location.

### `file-not-found`

**Error.** A file named on the command line does not exist.

<div class="error-output">

```
[file-not-found]
Error: No such file: Missing.es
```

</div>

Check the path.

Taught on: [Running tests](/docs/guides/running-tests)

### `not-a-file`

**Error.** A directory is named where a source file belongs.

<div class="error-output">

```
[not-a-file]
Error: src is a directory. Pass the source files inside it instead, for example src/*.es
```

</div>

Name the files inside it, for example `src/*.es`.

Taught on: [Command line › The shape of an invocation](/docs/reference/cli#the-shape-of-an-invocation)

### `unreadable-file`

**Error.** The file exists but cannot be read, usually because of its permissions.

<div class="error-output">

```
[unreadable-file]
Error: Not allowed to read Locked.es
```

</div>

Fix the file's permissions.

### `bundle-failed`

**Error.** The generated JavaScript could not be bundled. The message starts with `Could not bundle the generated JavaScript:`. This is a compiler bug.

Report it, with the program that caused it.

### `bundler-warning`

**Warning.** The JavaScript bundler reported a warning. The compiler passes it through unchanged.

Read the bundler's message. Your program still builds.

## Everything else

An `@` written where it names nothing, a standard-library declaration, and a failure inside the compiler.

### `at-outside-method`

**Error.** `@` is used outside a method or a `match` arm, where it names nothing.

<div class="error-output">

```
[at-outside-method]
Error: There is no '@' here to refer to
   ╭─┤ Me.es:2:16 │
   │
 2 │     constant me = @
   │                   ▲  
   │                   ╰── this is outside any Method or Handler
   │ 
   │ Note: '@' is the receiver of a Method or the value a Match Handler matched.
───╯
```

</div>

Use `@` inside a method, for its receiver, or inside a `match` arm, for the matched value.

Taught on: [Namespaces and methods › The receiver, `@`](/docs/language/namespaces-and-methods#the-receiver-)

### `at-in-static-method`

**Error.** `@` is used in a static method, which has no receiver.

<div class="error-output">

```
[at-in-static-method]
Error: There is no '@' in a static Method
   ╭─┤ Point.es:6:7 │
   │
 6 │          <- @
   │             ▲  
   │             ╰── this Method is called on the Namespace
   │ 
   │ Help: Take the value as a Parameter, or drop 'static' to make this an instance Method.
   │ 
   │ Note: '@' is the receiver of an instance Method, and a static Method is called without one.
───╯
```

</div>

Take the value as a parameter, or return a value built in the body: `static origin() -> Point { <- { x = 0, y = 0 } }`. Remove `static` instead when the method is meant to run on a value.

Quick Fix: **Drop 'static'**.

Taught on: [Namespaces and methods › The receiver, `@`](/docs/language/namespaces-and-methods#the-receiver-)

### `native-property-without-type`

**Error.** A static property in a `declarations { … }` file has neither a value nor a type. Only the standard library's own sources can hit this, because a program cannot open a `declarations` block (see [`declarations-outside-stdlib`](/docs/reference/diagnostics#declarations-outside-stdlib)).

Annotate the property with its type, as in `static Pi: Transcendental`.

### `internal-error`

**Error.** The compiler failed where it should have reported a problem. Apart from the install problem below, this is a compiler bug.

Report it, with the program that caused it. The one known cause outside the compiler is Yarn's Plug'n'Play install, under which `essence build` stops with this error. Switch the project to a `node_modules` folder.

Taught on: [Installation › Add it to a project](/docs/getting-started/installation#add-it-to-a-project)
